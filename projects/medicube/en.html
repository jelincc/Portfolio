Problem

The UI was teaching users the wrong way to connect

As new devices were added, supporting multiple devices at once became important, but the existing UI was built to show only a single connection state at a time. Users had no idea they could register several devices together, so they kept disconnecting the current one and re-registering a new one instead.

Hypothesis

If the app proposes the connection first, and registered devices can be managed from a single screen, pairing will get easier

Real usage data and VOC analysis showed that users struggled more with starting a connection than with the connection feature itself. We hypothesized that if the app could recognize connectable devices proactively, and let users manage registered devices from one screen, the pairing experience would improve.

Hypothesis ① Improving How Connections Start

If the app detects a powered-on device first and proposes the connection, the actual Bluetooth pairing rate will rise.

GA Data

Hypothesis ② Multi-Device Management Experience

If users can see and control every registered device from a single screen, the repeated disconnect-and-re-register behavior will drop.

GA Data

72% of users disconnected an existing device before connecting a different one, every time they switched. (Quantitative evidence of the repeated behavior)

"I didn't know you could register more than one."
→ The existing UI failed to communicate that the structure supports multiple devices.

Decisions · Final Design

Auto-Detection + One-Step Control

Auto-Detect · Quick Connect

When a powered-on device is nearby, the app detects it automatically and proposes a connection via bottom sheet.

Home Device List

All connectable devices are shown as a full list on the home screen. Registering several devices no longer gets bottlenecked by a single banner.

One-Step Control

For any already-connected device, a single tap from the list takes you straight to the control screen.

Separating UX Copy by Intent

Split copy meant to "confirm" from copy meant to "connect," so the next action is always clear.

Design Principle: Users in their 30s and 40s are much more likely to drop off the moment a flow goes two steps deep. Rather than add more features, our top priority was cutting the number of steps needed to reach an already-connected device.

What We Learned

Users had no idea they could register more than one device.

  • The old screen showed only a single device's status, which created the impression that only one connection was possible at a time.
  • Both the real data and our VOC analysis repeatedly showed the same pattern: disconnecting the current device before connecting a new one.
Key Insight

The problem was never the pairing feature itself — it was that the UI failed to communicate the structure that supported registering multiple devices.

→ Instead of adding features, we redesigned the UI so that "you can manage multiple devices" would be obvious at a glance, which carried through to improvements in the related metrics.

Wrapping Up the Project

Staying focused on the task at hand matters when introducing a new feature, but I came away with a clearer sense that I also need to design UX/UI with an eye on where the service is headed and the company's core business direction.

→ I already knew our company was focused on a device-centric business, but I hadn't given enough thought to what happens when users connect multiple devices — and that gap in consideration is exactly what created this pain point.
