핵심 인사이트: 문제의 절반 이상은 "몰라서"가 아니라 "먼저 물어보지 않아서" 생겼습니다. 매번 사용자가 연결 방법을 찾아야 했던 구조를, 디바이스가 켜지면 앱이 먼저 인식하고 제안하는 구조로 뒤집는 것이 핵심 방향이었습니다.
성공 기준: 설명 없이 이해 가능한 한손 조작 UI, 연동 사용률 상승, CS 문의 감소
Hypothesis

앱이 먼저 연결을 제안하고, 등록된 디바이스를 한 화면에서 관리할 수 있다면 연동 경험은 더 쉬워질 것이다

실사용 데이터와 VOC 분석 결과, 사용자는 연결 기능보다 연결을 시작하는 과정에서 더 많은 어려움을 겪고 있었습니다. 앱이 먼저 연결 가능한 디바이스를 인식하고, 등록된 기기를 한 화면에서 관리할 수 있다면 연동 경험이 개선될 것이라 가설을 세웠습니다.

가설 ① 연결 시작 경험 개선

전원이 켜진 디바이스를 앱이 먼저 인식해 연결을 제안하면, 실제 블루투스 연동률이 높아질 것이다.

GA 데이터

디바이스 등록자 중 실제 블루투스 연동 사용률은 약 45%에 머물렀습니다.
→ 등록은 했지만 연동은 하지 않는 사용자가 많다는 정량 근거

"전원을 켜면 자동으로 연결되는 줄 알았어요."
→ 자동 연결에 대한 오인

가설 ② 멀티 디바이스 관리 경험

등록된 디바이스를 한 화면에서 모두 확인하고 바로 제어할 수 있다면, 반복적인 해제·재등록 행동이 줄어들 것이다.

GA 데이터

사용자의 72%가 디바이스를 전환할 때마다 기존 연결을 해제한 뒤 다른 디바이스를 다시 연결했습니다. (반복 행동의 정량 근거)

"여러 대를 등록할 수 있는 줄 몰랐어요."
→ 기존 UI가 멀티 디바이스를 지원하는 구조를 전달하지 못하고 있다.

의사결정 · 최종 디자인

자동 인식 + 1단계 컨트롤

자동 인식 · 퀵연결

주변에 전원이 켜진 디바이스가 있으면 자동으로 인식해 바텀시트로 연결을 제안.

홈 디바이스 목록

연결 가능한 디바이스를 홈에서 전체 목록으로 노출. 여러 대를 등록해도 배너 하나로 막히지 않음.

1단계 컨트롤

이미 연결된 디바이스는 목록에서 한 번의 진입으로 바로 제어 화면 도달.

UX 라이팅 분리

"확인"이 목적인 문안과 "연결"이 목적인 문안을 구분해 다음 행동을 명확히 안내.

설계 원칙: 3040세대는 2단계 이상 들어가는 순간 이탈 가능성이 크게 높아집니다. 기능을 더 넣기보다 이미 연결된 디바이스까지 도달하는 단계를 줄이는 것을 최우선으로 삼았습니다.
Outcomes

기능을 더하지 않고 단계를 줄이는 방향으로,
디바이스 연동을 쉽게 만들다

화면이 하나의 디바이스 상태만 보여줘 '한 번에 하나만 연결할 수 있다'는 오해를 주고 있었다는 걸 사용성 테스트와 실제 데이터로 확인한 뒤, 자동 인식과 1단계 컨트롤로 두 차례에 걸쳐 문제를 좁혀갔습니다.

What We Learned

사용자는 여러 디바이스를 등록할 수 있다는 사실을 인지하지 못했습니다.

  • 기존 화면은 하나의 디바이스 상태만 노출해 '한 번에 하나만 연결할 수 있다'는 인식을 만들었습니다.
  • 실제 데이터와 VOC 분석 결과에서도 기존 디바이스를 해제한 뒤 새 디바이스를 연결하려는 행동이 반복적으로 관찰되었습니다.
Key Insight

문제는 연동 기능이 아니라, '여러 디바이스를 등록할 수 있다'는 구조를 UI가 전달하지 못한 것이었습니다.

→ 기능을 추가하기보다, 여러 디바이스를 관리할 수 있다는 구조가 자연스럽게 이해되도록 UI를 재설계했고, 관련 지표 개선으로 이어졌습니다.

프로젝트를 마치며

신규 기능 도입 시 주어진 과업에 집중하는 것도 중요하지만, 앞으로의 서비스 확장성과 회사의 핵심 사업 방향까지 고려하며 다양한 시각으로 UX/UI를 설계해야겠다는 인사이트를 얻었습니다.

→ 자사가 디바이스 중심 사업에 집중하고 있다는 점은 인지하고 있었지만, 다수 디바이스 연결 흐름에 대한 충분한 고려가 부족해 해당 Pain Point가 발생했다고 판단했습니다.
